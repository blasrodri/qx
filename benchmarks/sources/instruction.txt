You are preparing a compact field guide for engineers who must deploy a local language model on a laptop with unified memory. Write for a reader who understands software systems but has not built an inference runtime. Begin by stating the operational goal and the hardware constraints. Explain why model size on disk, peak physical footprint, steady-state footprint, first-token latency, and decode throughput are separate measurements. Give a short example in which a smaller file still creates a larger process because weights are copied into multiple buffers. Then describe a disciplined evaluation procedure.

The procedure must pin the source revision, compiler options, model artifact, tokenizer, operating-system build, power mode, and benchmark token stream. It must compare release binaries under the same context length and generation count. It must alternate the execution order of the two engines so that thermal drift does not consistently favor one side. It must record every paired observation, reject runs that cross a thermal-state transition, and report a confidence interval over paired differences. Do not imply that seven repetitions are enough for a close performance claim.

Next, explain quality evaluation. Compare each quantized candidate with the same higher-precision reference. Report negative log likelihood, perplexity, distribution divergence, logit similarity, and task accuracy. Keep calibration examples separate from held-out examples. Explain why a candidate that matches another quantized engine can still be poor if both have drifted from the original model. Mention that approximations such as reducing the number of active experts belong after the quality-neutral execution path is mature.

Close with a deployment checklist. The checklist should verify that model state remains on the accelerator during decode, no temporary allocation occurs in the token loop, synchronization has no hidden CPU waits, and only the selected token returns to the host. It should also verify load-time and steady-state memory, recovery behavior when a plan is unsupported, and reproducibility of the selected execution plan. Use direct language, short paragraphs, and concrete units. Avoid marketing language. The reader should finish with a procedure they can execute and audit.
